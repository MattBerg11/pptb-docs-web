# Impersonation

Need to check what another user can see or do in Dataverse? Impersonation lets a tool send its Dataverse requests on behalf of another user, using your existing connection. You do not need that user's credentials. {{ className: 'lead' }}

<RequiresVersion>1.2.7</RequiresVersion>

## Overview {{ anchor: true }}

Impersonation is useful when you want to:

- Test a user's security roles before they report a problem
- Check which records a user can read or update
- Reproduce an "access denied" error that only one user sees
- Create or update records on behalf of another user

How it works:

- Impersonation is set **per open tool tab and per connection**
- Other tabs are not affected, even if they use the same connection
- A tool opened on the same connection starts without impersonation
- Impersonation is not saved. Closing the tab or the app ends it.

Behind the scenes, Power Platform ToolBox adds the `CallerObjectId` header to the tool's Dataverse requests. Dataverse then runs those requests as the selected user. See Microsoft's [Impersonate another user](https://learn.microsoft.com/power-apps/developer/data-platform/impersonate-another-user) for details.

## Before You Start {{ anchor: true }}

Impersonation is enforced by Dataverse, not by Power Platform ToolBox. Before you start, check the following:

- **Your account needs the "Act on Behalf of Another User" privilege** (`prvActOnBehalfOfAnotherUser`). The **Delegate** security role includes it.
- **The privilege must be assigned to your user directly.** Dataverse does not allow it to be inherited through a team.
- **The user you impersonate must be enabled** and linked to a Microsoft Entra ID account. Disabled users and users without an Entra object ID are not listed.

<Note type="information">
  Dataverse uses the **overlap** of your privileges and the impersonated user's privileges. An action only succeeds if both of you are allowed to do it. Impersonation cannot give anyone more access than they already have.
</Note>

<Note type="warning">
  Records you create or update while impersonating are saved as the impersonated user. Dataverse records your account in the **Created By (Delegate)** and **Modified By (Delegate)** columns. Be careful when impersonating in production environments.
</Note>

## Start Impersonating {{ anchor: true }}

### When you open a tool

1. Open a tool from the sidebar.
2. In the connection screen, select the connection you want to use.
3. Check **Impersonate as another user** under that connection.
4. Confirm your connection.
5. The **Impersonate User** window opens. [Choose a user](#choose-a-user).

The tool opens with impersonation already active.

### On a tool that is already open

1. Right-click the tool's tab.
2. Select **Change Connection** (or **Manage Connections…** for tools that use more than one connection).
3. Check **Impersonate as another user** under the connection.
4. Confirm, then [choose a user](#choose-a-user).

For additional connections (Connection 2 and up), you can also use the status bar:

1. Right-click the connection square in the status bar.
2. Select **Impersonate…**.
3. [Choose a user](#choose-a-user).

## Choose a User {{ anchor: true }}

The **Impersonate User** window shows the connection name and environment at the top, so you know which connection you are choosing for.

- The list shows enabled users in that environment, sorted by full name
- Type in the search box to find users by **name or email**
- Select **Load more** to see more results
- Click a user to start impersonating them
- Select **Skip** (or close the window) to continue **without** impersonation

<Note type="information">
  If the user list cannot be loaded, the window shows an error. Search again, or select **Skip** to continue without impersonation.
</Note>

## Know When It Is Active {{ anchor: true }}

Power Platform ToolBox shows impersonation in three places:

| Where | What you see |
| --- | --- |
| **Tool tab** | An impersonation icon on the tab. Hover to see who you are impersonating. |
| **Banner above the tool** | "Dataverse impersonation active", followed by the user for the primary connection and, if set, Connection 2. |
| **Status bar** | Additional connection squares show an impersonation icon. Hover to see the user's name. |

## Change or Stop Impersonating {{ anchor: true }}

### Primary connection

1. Right-click the tool's tab.
2. Select **Change Connection** (or **Manage Connections…**).
3. Choose what you want:
   - **Change user:** keep **Impersonate as another user** checked and pick a different user
   - **Stop:** leave **Impersonate as another user** unchecked and confirm

<Note type="information">
  Confirming **Change Connection** or **Manage Connections…** always applies the checkbox state. If you confirm with the box unchecked, impersonation is turned off for that connection.
</Note>

### Additional connections

Right-click the connection square in the status bar, then select:

- **Change Impersonated User…** to pick a different user
- **Stop Impersonating** to go back to your own account

<Note type="important">
  Switching a connection to a different environment ends impersonation for that connection. Clearing a connection does the same.
</Note>

## Multiple Connections {{ anchor: true }}

For tools that use more than one connection, impersonation is set **separately for each connection**. For example:

- Primary connection: impersonating a sales user
- Connection 2: your own account

You can also assign the **same connection** to more than one slot and impersonate a **different user** in each. This makes it easy to compare what two users can see in the same environment, side by side. The connection screen warns that the connection is "Also assigned to another slot". This is expected, and you can still confirm.

See [Authentication: Multiple Connections](/authentication#multiple-connections) for how multi-connection tools work.

## What Gets Impersonated {{ anchor: true }}

Impersonation applies to Dataverse **data** operations made by the tool:

| Impersonated | Not impersonated (runs as you) |
| --- | --- |
| `create`, `retrieve`, `update`, `delete` | `executeBatch`, `executeTransaction` |
| `createMultiple`, `updateMultiple` | Metadata reads (`getEntityMetadata`, `getAllEntitiesMetadata`, `getEntityRelatedMetadata`, `getCSDLDocument`) |
| `retrieveMultiple`, `fetchXmlQuery`, `queryData` | `getSolutions`, `publishCustomizations`, `deploySolution`, `getImportJobStatus` |
| `associate`, `disassociate` | Table, column, relationship, and option set changes |
| `execute` (actions and functions) | Power Platform API calls |

<Note type="warning">
  If a tool uses batch operations, metadata, or the Power Platform API, those requests still run as **your** account. Results from those calls do not reflect the impersonated user's access.
</Note>

## For Tool Developers {{ anchor: true }}

You do not need to write any code to support impersonation.

- The user turns impersonation on in the ToolBox UI, not in your tool
- ToolBox adds the `CallerObjectId` header for the [impersonated operations](#what-gets-impersonated) on the matching connection
- Your tool keeps calling the [Dataverse API](/tool-development/api-reference/dataverse-api) as usual
- There is currently no tool-facing API to read or change the impersonation state

Design your tool to handle permission errors cleanly. When a user impersonates someone with fewer privileges, calls that normally succeed may return "access denied" errors. See [Error Handling](/tool-development/api-reference/error-handling).

## Troubleshooting {{ anchor: true }}

### Requests fail with a privilege error

**Cause:** Your account does not have the "Act on Behalf of Another User" privilege, or it is only granted through a team.

**Solution:**

- Ask an administrator to assign the **Delegate** role (or a role with `prvActOnBehalfOfAnotherUser`) to your user directly
- Reconnect, then try again

### A user is missing from the list

**Possible causes:**

- The user is disabled in Dataverse
- The user has no Microsoft Entra ID object ID (for example, some system or stub users)

Search by email address if a name search does not find them.

### Results look like my own access

**Possible causes:**

- The tool is using batch, metadata, or Power Platform API calls, which are [not impersonated](#what-gets-impersonated)
- Impersonation was set on a different connection slot than the one the tool is using
- The tab was duplicated or reopened. New tabs start without impersonation.
